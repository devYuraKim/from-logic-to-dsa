# DSA ROADMAP (V1)

## I. 모델 A: 엔지니어링 빌드업 로드맵 (Bottom-Up)
언제 쓰나: 다음에 무엇을 공부할지 결정할 때

### 엔지니어링 빌드업 로드맵 (Bottom-Up)

| 수준    | 주요 주제 (Concept)          | 핵심 도구 (Tools)             | 핵심 연결 포인트 (Insight) | 다음 목표 (Next Action)              |
|:------|:-------------------------|:--------------------------|:--------------------|:---------------------------------|
| **5** | **최적화 (DP)**             | `Memoization`, 점화식        | "중복 상태 제거 + 최적값 축적" | `Coin Change`, `Knapsack` 구현     |
| **4** | **최단경로 (가중치)**           | `PriorityQueue`, `Heap`   | "비용이 가장 작은 상태부터 확장" | **다익스트라(Dijkstra)** 경로 탐색        |
| **3.5** | **그래프 표현**               | 인접 리스트, 입력 파싱             | "문제를 그래프로 모델링"      | `Map<Integer, List<Integer>>` 구현 |
| **3** | **탐색의 기초**               | DFS, BFS, `visited`       | "상태 공간 탐색 + 중복 방지"  | DFS/BFS 반복 숙달                    |
| **2.5** | **상태 제어**                | 재귀 + 상태 복구                | "상태를 변경하고 되돌림"      | 순열/조합                            |
| **2** | **선형 구조**                | `Stack`, `Queue`, `Array` | "상태 저장 컨테이너"        | `ArrayDeque` 활용                  |
| **1** | **기초 체력**                | `for`, `if`, 기본 문법        | "로직을 코드로 번역"         | 매일 10분 '기초 문법 카타'                |

---

### 핵심 연결 고리 (Connection Points)
- `visited` (**DFS/BFS**): Boolean 상태 → 중복 방문 방지
- `dist` (**BFS/Dijkstra**): 거리/비용 상태 → 최단 경로
- `memo` (**DP**): 상태 결과 저장 → 중복 계산 제거

**상태를 어떻게 저장하고 갱신하느냐의 차이**

## II. 모델 B: 알고리듬 논리 계보 로드맵 (Top-Down)
언제 쓰나: "**개념들이 어떻게 서로 연결되고 파생되었는가**"를 파악할 때

### 알고리듬 논리 계보 로드맵 (Top-Down)

| 레이어       | 개념 (Concept)     | 핵심 도구 (Tools) | **재해석 (DP 기준)**                  | 다음 액션 (Next Action)          |
|:----------|:-----------------| :--- |:---------------------------------|:-----------------------------|
| **5층**    | **DP (최적화)**     | `memo`, `dp[]`, 점화식 | "상태를 저장하고 재사용하여 최적화"             | `Coin Change`, `Knapsack` 완성 |
| **4층**    | **Dijkstra**     | `PriorityQueue`, `dist[]` | "가중치 있는 DP"                      | 가중치 그래프 최단경로 풀이              |
| **3층**    | **BFS**          | `Queue`, `dist[]` | "가중치=1인 거리 기반 DP"                | 최단거리 / 미로 탐색                 |
| **2층 발전** | **Backtracking** | 재귀 + 상태 복구 | "DP 없이, DFS + 상태 변경 + 복구(경로 제어)" | 순열/조합 탐색                     |
| **2층**    | **DFS**          | 재귀, `visited` | "DFS에 memo 추가 시 DP"              | 재귀와 스택의 구조적 이해               |
| **1층**    | **자료 구조**        | `Stack`, `Queue`, `Array` | "상태 저장소"                         | 자료구조의 특성 완벽 숙지               |

### 핵심 연결
**DFS** → ($+memo$) → **DP** → ($w=1$) → **BFS** → ($+가중치$) → **Dijkstra**

## III. 문제 선택 프레임워크

1. 모든 경우를 봐야 하나? → DFS / Backtracking

2. 최단 거리인가? → BFS / Dijkstra

3. 중복 계산이 있는가? → DP

4. 상태 정의 가능한가? → DFS / DP

## [참고] 초고도 영역의 이해

5단계에서 1-4단계 완벽하게 닦으면 됨. 6-8 같은 게 있다 정도로만 이해하자.     

#### [알고리듬 고도화의 본질] 
- 1~5단계 (Deterministic): "명확한 규칙(로직)으로 100% 정답을 찾아내는 과정"     
- 6~8단계 (Probabilistic/Scalable): "현실적인 제약(시간, 데이터 크기) 속에서 최선의 대안을 찾아내는 과정"

#### 1. 6단계: 휴리스틱과 근사 (Heuristics & Approximation)     
DP로도 풀 수 없는 NP-Hard 문제(예: 외판원 순회 문제 - TSP)들을 만났을 때.
- 개념: "완벽한 정답은 포기한다. 하지만 충분히 쓸만한 답을 빠르게 찾겠다."     
- 도구: A* 알고리듬, 유전 알고리듬(Genetic Algorithm), 시뮬레이티드 어닐링.
- 차이: DP는 100% 최적해를 보장하지만, 여기서는 '**가장 그럴싸한 길**'을 감으로(휴리스틱) 찾아냄.

> - **진짜 의도**: "이 문제가 DP로 안 풀린다는 걸 논리적으로 증명할 수 있는가? (시간 복잡도 계산)"     
> - **기대하는 답변**: "이 문제는 모든 경로를 다 봐야 하므로 $O(n!)$이 걸립니다. 현실적으로 불가능하니, 그리디(Greedy)나 근사 알고리듬을 써서 최적은 아니더라도 합리적인 답을 찾겠습니다."

#### 2. 7단계: 분산 처리와 병렬화 (Distributed Computing)
데이터나 연산의 규모가 한 대의 컴퓨터(Memory/CPU)를 넘어설 때.
- 개념: "혼자서 DP를 돌리기엔 너무 크다. 수만 대의 컴퓨터로 쪼개서 풀자."     
- 도구: MapReduce, Spark, 분산 락(Distributed Lock), 샤딩(Sharding).     
- 차이: 알고리듬의 논리보다 **데이터의 이동과 네트워크 지연(Latency)**을 관리하는 것이 핵심.

> - **진짜 의도**: "데이터가 너무 커서 메모리에 안 들어가면 어떡할래?"
> - **기대하는 답변**: "데이터를 100대로 쪼개서(Sharding) 각각 처리한 뒤 나중에 합치겠습니다(MapReduce 방식)."

#### 3. 8단계: 기계학습과 인공지능 (Machine Learning)
   로직을 사람이 짜는 단계를 넘어, 데이터로부터 로직(모델)을 추출하는 단.

- 개념: "점화식을 사람이 세우지 않고, 데이터가 스스로 파라미터를 찾게 한다."     
- 도구: 신경망(Neural Networks), 경사 하강법(Gradient Descent).     
- 차이: 결정론적인(Deterministic) 알고리듬에서 확률론적인(Probabilistic) 판단으로 패러다임 전환.
